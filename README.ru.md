# XDuck — перекрёстный дакер / гейт / текстура для Zoom MS-70CDR

[English version](README.md)

![XDuck на экране MS-70CDR](docs/screen.png)

**Релиз 1.19.** Свой эффект `.ZDL` для **Zoom MS-70CDR** (прошивка 2.10).
Громкость одного входа управляет громкостью другого. Инструмент — в **IN L**,
драм-машина / бочка / луп — в **IN R**, и инструмент «качается», гейтится или повторяет
динамику барабанов.

В паре с эффектом-напарником **[sForm](https://github.com/Senty3kat/sForm-ZDL-MS70CDR)**
(LFO с гибкой формой волны и одноголосный синт): цепочка sForm → XDuck с Route = `sForm`
заставляет XDuck точно, сэмпл за сэмплом, повторять волну sForm — тремоло, транс-гейт,
автопанорама, модуляция на частоте сыгранной ноты. См. [Работа с sForm](#работа-с-sform).

> **Только MS-70CDR.** Эффекту нужны два раздельных входа педали (IN L / IN R).

## Установка

1. Скачай [`release/XDuck.ZDL`](release/XDuck.ZDL) и [`release/XDuck.png`](release/XDuck.png)
   (PNG — картинка для Effect Manager, клади рядом с ZDL).
2. Закрой Ableton и вкладки браузера с Web MIDI — они занимают порт педали.
3. Установи через Zoom Effect Manager. Эффект в категории **Dynamics**, номер **501**.
   - Effect Manager не заменяет эффект с тем же номером: старый XDuck 1.16+ сначала удали.
   - XDuck **1.13 и старше** имел номер 486 и категорию Delay (номер совпадал с эффектом
     из другого набора). Для педали это другой эффект: удали его вручную, а в старых
     патчах поставь XDuck заново.
4. Ставь XDuck **первым** в патче — тогда ключ из IN R приходит чистым
   (или сразу после sForm, см. ниже).

Если педаль зависла: выключить, зажать левую ручку, включить, *All Initialize*, футсвич.

## Экран

Одно окошко внизу слева. Вместо крутилки в нём значок первой ручки текущей страницы:
на 1-й странице это **Type** — уточка для `Duck`, импульс для `Gate`, волны для `Tex`.

## Ручки (3 страницы)

| Стр. | Ручка | Что делает |
|---|---|---|
| 1 | **Type** | `Duck` — ключ громче → сигнал тише (качание). `Gate` — ключ громче → сигнал открывается. `Tex` — громкость сигнала плавно следует за ключом, оба звука смешаны в оба выхода. |
| 1 | **Route** | `X` — R управляет L и L управляет R. `R>L` — R управляет L, R проходит. `R<L` — L управляет R, L проходит. `KeyR` — R управляет L, сам R не слышен. `KeyL` — L управляет R, сам L не слышен. `sForm` — в R приходит волна sForm, L идёт по ней (см. ниже). `sFPan` — как `sForm`, но правый выход идёт по волне со сдвигом 180°: автопанорама. |
| 1 | **Freq** | На что реагирует детектор: `Full` или полоса вокруг 40…8k Гц (бочка ≈ 60–100, малый ≈ 150–230, хэты ≈ 5.1k–8k). Сам звук не фильтруется. |
| 2 | **Thrsh** | Порог ключа 0…60 = 0…−60 дБ. Больше число — реагирует на более тихий ключ. |
| 2 | **Range** | Максимальное ослабление 0…60 дБ (глубина дакинга / пол гейта). |
| 2 | **Ratio** | Duck: крутизна компрессии, 100 = лимитер. Gate: жёсткость, 100 = жёсткий гейт. Tex: 100 = следование дБ в дБ. |
| 3 | **Attk** | 0.1…100 мс. Duck: как быстро приседает. Gate/Tex: как быстро открывается. |
| 3 | **Hold** | 0…500 мс. Удерживает уровень ключа после удара: дак не отпускает, гейт не дребезжит. |
| 3 | **Rels** | 5 мс…2.5 с. Duck: возврат (то самое «качание»). Gate/Tex: как быстро закрывается. |

Выход всегда 100 % обработанный (ручки Mix нет).

### Быстрые настройки

- **Сайдчейн-качание:** Type `Duck`, Route `KeyR`, Freq `60`, Thrsh 40, Range 40, Ratio 80, Attk 15, Hold 10, Rels 45.
- **Транс-гейт от хэтов:** Type `Gate`, Route `KeyR`, Freq `5.1k`, Hold 5, Rels 20.
- **Два музыканта приглушают друг друга:** Type `Duck`, Route `X`.

## Работа с sForm

Цепочка **sForm → XDuck** (sForm сразу перед XDuck), у sForm **Out = `XDuck`**, у XDuck
**Route = `sForm`** или **`sFPan`**. sForm передаёт свою волну по каналу R, XDuck читает её
на каждом сэмпле, без детектора и огибающей, поэтому точно повторяет форму на любой
частоте — от медленной волны в сотню секунд до модуляции звуковой частоты или на высоте
сыгранной ноты (sForm Note = `in…`). Обработанный L идёт на оба выхода.

В этих режимах:

| Type | Громкость L |
|---|---|
| `Duck` | 1 − волна (громче, когда волна внизу) |
| `Tex` | повторяет волну |
| `Gate` | открывается, где волна пересекает **Thrsh** (30 = середина волны, меньше — открыт дольше); **Ratio** — крутизна (0 = просто идёт по волне, 100 = резкое вкл/выкл) |

**Range** — глубина для всех трёх. Attk, Hold, Rels и Freq не действуют.
`sFPan` даёт каждой стороне свою копию волны со сдвигом на полпериода — автопанорама
(есть только в этих режимах, где L идёт на оба выхода).

## Что выяснилось про железо

- Буфер эффекта (`ctx[5]`) несёт настоящие IN L и IN R в двух половинах по 8 сэмплов.
- «Сырой» входной буфер (`ctx[4]`) несёт **только IN L** — его правая половина пустая,
  поэтому «чистого» R до цепочки нет. Отсюда «ставь XDuck первым».
- Окошки значений — только **горизонтальным рядом**; столбиком рисовалась лишняя полоса.
  Окошко у самого левого края (x = 0) закрывает плашка «слева есть эффект» — у XDuck оно
  на x = 14, как первое окошко у заводских эффектов.
- Имена ручек длиннее 5 букв налезают друг на друга на экране.
- Ручка больше чем на 102 положения (max > 101) — Effect Manager не записывает эффект
  (`FS.bin size mismatch`).

## Сборка из исходников

Собирается тулчейном [themanro/ZoomMultistompZDL](https://github.com/themanro/ZoomMultistompZDL)
(форк [repeat98/ZoomMultistompZDL](https://github.com/repeat98/ZoomMultistompZDL))
и компилятором TI C6000 8.5.0.LTS (идёт с Code Composer Studio).

1. Склонируй форк themanro и скопируй `src/xduck/` в `src/custom/xduck/`.
2. Скопируй файлы из `toolchain-patches/` поверх тех же путей в форке (это целые файлы,
   основа — форк на 2026-10-18; с более новым форком может понадобиться слияние). Они добавляют:
   - `build/linker.py` — одно окошко значения (`allow_fewer_knob_boxes`) и свою картинку
     крутилки (`knob_pic`, `knob_frames`, заводской «style 12»);
   - `build/selector_metadata.py` — слова на экране для Type / Route / Freq (и для sForm);
   - `build/parameter_display.py` — 5-буквенные имена Thrsh / Attk / Rels;
   - `src/airwindows/common/pack_covers.py` и `custom_covers.py` — экраны XDuck и sForm.
3. В `src/custom/xduck/build.py` укажи `TI_ROOT` (компилятор) и `out_dir` (куда класть ZDL)
   и запусти `python src/custom/xduck/build.py`.

DSP (`xduck.c`) по правилам безопасного DSP форка: без switch, без математической
библиотеки, без деления, без static-массивов, состояние в арене `ctx[3]`, `ctx[11]`/`ctx[12]`
сохраняются.
